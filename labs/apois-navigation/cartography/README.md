# Cartografia experimental APOIS
Source: same verified regional Geofabrik OSM extract as Valhalla (bbox -40.80,-9.65,-40.20,-9.10). Planetiler v0.10.2 jar SHA-256 pinned. Custom MVT schema, PMTiles v3, zoom 8–15; geometry only. No basemap service, Google data, user locations, or infrastructure purchase.
Ferrostar 0.59.0 declares MapLibre Compose 0.13.0; that release declares Android SDK 13.0.2. Official native PMTiles support documented since 11.7.0. References: https://github.com/stadiamaps/ferrostar/blob/0.59.0/android/gradle/libs.versions.toml ; https://github.com/maplibre/maplibre-compose/blob/v0.13.0/gradle/libs.versions.toml ; https://maplibre.org/maplibre-native/android/examples/data/PMTiles/ . Actual device rendering remains untested.
Style template uses an intentionally non-resolving .invalid URL; no map server configured. Road/place names retained as attributes; no symbol layers until self-hosted licensed glyphs are available. The neutral basemap preserves contrast for the existing red APOIS route/puck; not a replacement for the approved app interface.
CI measures archive bytes, tile counts, build wall time and peak process RSS (GNU time); no APK. Header/metadata verification is not a visual or completeness test. Subsequent gates: decode sample MVTs, verify river/bridge/streets, glyphs and attribution, HTTP 206 range/ETag, native rendering at real zoom, bandwidth and update policy. OSM data ODbL: https://www.openstreetmap.org/copyright ; distribution of derived database must satisfy applicable ODbL obligations. No public OSM tile endpoints. Do not publish until authorized.

## Static hosting transport gate
CI additionally starts a disposable Nginx bound only to 127.0.0.1; filename contains the archive SHA-256 and the response disables gzip transformations. Tests check 206 range byte identity, Content-Range, consistent ETag, 416 for out-of-range and 304 conditional responses. No deployment, TLS, CDN or mobile download is claimed. Candidate architecture: immutable PMTiles object + style and glyph assets served with HTTPS and validated byte ranges; separate authenticated Valhalla route endpoint. Actual traffic/cost sizing awaits archive and device metrics.

## Local bundled basemap experiment
Run 45539027853 passed: all 3296 MVTs decoded, 3693 distinct road/place names, all 100 required glyph codepoints present, 84359 bytes of glyphs. Native 13.0.2 docs explicitly support pmtiles://asset:// and pmtiles://file:// but PMTiles does not support SDK offline-pack downloads/caching: https://github.com/maplibre/maplibre-native/blob/android-v13.0.2/platform/android/docs/data/PMTiles.md . CI now builds a local assets directory with local-only style, map, glyphs, attribution and license; each entry has size and SHA-256. Kotlin BundledRegionalMap verifies the trusted packaged assets on IO dispatcher and returns local style or null; no downloader and no change to APK assembly. Hash manifest ensures integrity, not authenticity of a downloaded untrusted manifest. A real APK/device test is still needed for PMTiles and glyph asset reads. ODbL publication obligations and source availability must be reviewed before distributing map data. No automated map updates or routing offline.

## Android range-reader correction
Although the native documentation advertises asset PMTiles, the exact Android 13.0.2 AssetManagerFileSource::request passes only resource.url to its worker, not resource.dataRange, and reads the full asset buffer: https://github.com/maplibre/maplibre-native/blob/android-v13.0.2/platform/android/MapLibreAndroid/src/cpp/asset_manager_file_source.cpp . Avoid relying on this path. BundledRegionalMap instead verifies and copies the archive to context.noBackupFilesDir/apois-regional/vale-<sha256>.pmtiles, uses a same-directory temporary file + fsync + rename, and returns an in-memory BaseStyle.Json with pmtiles://file:///... . Glyphs remain asset:// because they are complete small files. No shared storage or additional permissions. The packaged asset and private copy both consume storage (roughly twice map size). Reuse verified files; retain old versioned files until a future safe cleanup policy knows no renderer is using them. The map is not opened in a device yet and this implementation is not registered in production.

## Bundled version lifecycle
Workflow 45539272618 generated 3,524,826 bytes of complete assets; both Android and host workflows passed for 2d7a1d2. PrivateMapStore now uses a process-lifetime exclusive file lock; only a successful first open in a new owner may clean old managed filenames, after verification of the selected version. Active paths are immutable and never removed/replaced within that process. Corruption of an already-issued path fails closed until restart; corruption before first use can be repaired from trusted APK assets. Partial/failed installs are staged and removed; up to three issued map versions per process. No remote update endpoint: the map version is currently changed via a future signed app package. No automatic deletion of unrelated files, no fallback to unverified old data. Device-level rendering and actual cross-process Android behavior remain untested.

## Host entry and asset merge gate
BundledLiveNavigationSurface is an unregistered opt-in Compose entrypoint; it loads and verifies the map before mounting LiveNavigationSurface (thus before GPS/voice). On failure only explicit host-mediated return/external intents are available, with no phase mutation. Current production and existing fake replay are not changed. Cartography CI now copies its generated assets into the disposable probe only and runs Gradle :probe:mergeDebugAssets; checks merged file names, sizes and hashes against the generated manifest. This is asset-merge verification, not APK generation or an authenticated host/device integration. The map uses the signed-app bundled update channel only; remote signed update and server deployment remain separate decisions.
