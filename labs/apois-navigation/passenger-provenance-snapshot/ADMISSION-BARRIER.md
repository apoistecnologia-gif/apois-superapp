# Barreira de admissão PostgreSQL → SQLite (laboratório)
A reconciliação anterior tinha uma janela reproduzida: revogação confirmada no PostgreSQL depois de ler os tombstones e antes de admitir no SQLite. A barreira experimental usa uma transação PostgreSQL READ COMMITTED e LOCK TABLE apois_nav_lab.revoked_leg IN SHARE MODE, lê o snapshot completo sob o lock e só libera após a admissão SQLite. O gateway exige confirmação do COMMIT; falha ou perda de confirmação nega o encaminhamento, mesmo que o token tenha sido consumido. O teste com outra sessão confirma a espera do escritor e as duas ordens possíveis. O escopo é a revogação gravada pela fixture: fase, cancelamento, reatribuição, alteração de autoridade e perda de vínculo. Reabertura automática de fase revogada não existe.
Não é uma transação distribuída PostgreSQL/SQLite. Uma rota admitida antes da revogação pode terminar depois dela. O lock global é intencionalmente conservador e não é candidato a produção sem avaliar latência, contenção, disponibilidade, ordenação, todas as mutações reais e política de revogação de sessão Auth. A perda de uma conexão pode consumir um token sem encaminhar a rota. A autoridade remota real e o schema de produção permanecem não confirmados. Nenhum SQL deste laboratório é uma migração.
