# Host de recuperação e transporte
Módulos opt-in, sem importação pelas rotas atuais. createVerifiedHostTransport adapta getSession/getUser(access_token) e functions.invoke com Authorization explícito do usuário verificado, sem armazenar ou logar tokens. A função de controle candidata é apois-navigation-control, ainda não implantada. createCreationInterlock usa Web Locks por conta, no mesmo origin, para coordenar a criação experimental com todos os caminhos convencionais: o host deve envolver o submit inteiro antes de reservar o journal e envolver as invocações ordinárias de criação. A consulta de corrida ativa falha fechado. O modo desativado não consulta banco nem storage. O mountDurablePassengerHost oferece revisão, recuperação, selagem e retorno, usando MapLibre injetado e catálogo aprovado. O tracker callback não altera estado de corrida; deve abrir o rastreador existente após confirmar autorização. Antes de usar na UI real é necessário instalar o interlock em todos os pontos de criação do build final, vincular lifecycle de conta/app, usar dados de catálogo reais aprovados, map provider local e verificar Web Locks/IndexedDB no Android. Não montar em produção, não ativar feature e não chamar endpoints existentes para testes.
