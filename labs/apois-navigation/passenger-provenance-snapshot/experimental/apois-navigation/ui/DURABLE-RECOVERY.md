# Recuperação durável do Passageiro
Módulos isolados, sem alteração de telas oficiais. O host somente pode abrir após identidade verificada e consulta autoritativa da corrida ativa. IndexedDB com transação readwrite durability=strict é obrigatório; falha de storage bloqueia envio. Guarda somente selectionId, requestKey e nonce de propriedade, por conta autenticada; não guarda endereço, GPS, credenciais, preço ou dados de perfil. Persiste antes do envio e mantém registro até corrida terminal confirmada ou selagem server-side da seleção sem corrida. Reinício nunca reenvia criação. Recuperação é leitura; selagem exige ação explícita, não cancela corrida. Se uma corrida existe, encaminhar para rastreador normal em vez de criar outra. Ainda é preciso ligar a guarda em TODOS os caminhos de criação do host, usar consulta real de corrida ativa, confirmar a mesma origem WebView e validar comportamento Android após encerramento/limpeza de armazenamento. O backend deve garantir selagem serializada com criação e rejeitar seleção selada. O jornal não é proteção contra cliente malicioso ou perda deliberada do banco local.
