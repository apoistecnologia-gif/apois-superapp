# Passive GPS handoff — lab only
Source inspection: superapp gitlink sources/apois-corridas-motorista-admin points to 9fc171050d8b5703540c49d19a8f1e9f5162775f; .gitmodules names the historical franciel046631 remote. Its migrated apoistecnologia-gif repository returned DriverLocationService.java at that exact commit (blob e60bf4429abbf8b96e76c29a08407d2b4a8d5ae6). The historical remote could not be read through the connector.
The existing service registers FusedLocationProviderClient on the main looper, requests high accuracy every 5s (minimum 3s), persists a pending position for presence recovery, and sends driver_set_presence through a network executor. The QA290 host installer changes movement threshold to 0m, preserving stationary fixes, and adds startup ACK. The pending buffer is not a navigation feed: it may be cleared on successful upload or contain restored positions up to 120s old.
The laboratory DriverGpsFeed accepts only direct Location callbacks, copies them, checks freshness using monotonic time and wall timestamp, rejects mock or invalid locations, rejects duplicates and imprecise fixes, and converts accepted data through Ferrostar 0.59.0 Location.toUserLocation(). A single consumer, separate source identity and consumer identity, and a current-session predicate prevent late deliveries. Watchdog runs only during subscription and does not query GPS. Initial thresholds (15s freshness, 35m horizontal accuracy, 750ms minimum processing interval) are lab choices, not validated production values. Guidance must pause on IMPRECISE/LOST, not advance arrival or ride state, and resume only on accepted fresh position.
Next integration gate: instrument a disposable copy of the generated QA290 host service only; start source after authorized tracking begins, publish synchronously from the existing tracking callback, end source on stop/destroy and account transition, verify final generated source and actual host dependencies. No integration into the operational service, manifest, demo, or UI is performed yet. No APK, extra GPS listener, or production modification. A physical test must measure actual fix cadence, frame smoothness and battery impact; compilation or unit tests do not prove those properties.

## Disposable service integration
The host compatibility workflow now checks out the exact public migrated Motorista source commit without persistent credentials, runs the existing QA290 driver installer inside a temporary scaffold, and compiles a passive instrumented copy in the Capacitor lab. It does not register that service in the manifest or execute its network code. The QA235 insertion point is tested separately with an anchor-shaped copy; full generated QA235/236/239 host is not yet compiled. Source START/STOP/destroy invalidates the old source epoch; subscribers never migrate to another epoch and cached fixes predating source start are rejected. Before real account integration the host must explicitly invalidate navigation on logout/account switch (including a token-only account transition), and rearm only a verified current ride. No production edits.
