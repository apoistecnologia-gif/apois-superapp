# Transporte remoto de cotação (candidato, não implantado)
O Edge de Corridas precisa alcançar um servidor separado; localhost na Edge não é o VPS. Este adaptador aceita endpoint HTTPS explícito /quote/route, autenticação HMAC dedicada, validade 15s, nonce único, digest do corpo normalizado, pseudônimo por conta, limites e SQLite persistente separado. O gateway continua loopback-only; TLS deve terminar em proxy confiável com host explícito, certificado válido, acesso apenas ao caminho de cotação, sem acesso ao Valhalla bruto ou gateway de motorista. Não enviar segredo ao cliente, reutilizar service role, usar túnel público, Google ou OSRM de terceiros. Segredo 32 bytes gerados fora do repositório; chave de produção e host não configurados. Verificador suporta duas chaves para rotação, mas rotação modifica o pseudônimo/limite e exige drenar/validar; sem reset do store. O proxy TLS no CI é sintético, não configuração de produção. A prova de autorização depende do Edge verificar a seleção e sessão antes de assinar; o gateway não consulta usuários. No backend candidato, injetar createRemoteQuoteMetrics({endpoint,keyId,secret,authUserId}) em independentMetrics; nenhuma mudança no endpoint implantado. Para o piloto ainda faltam TLS público autorizado, firewall, supervisão, atualização/backup, métricas, limites e medição física/remota de custo. Não confundir a cotação de passageiros com os permits Ed25519 de motoristas.
